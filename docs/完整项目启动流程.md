# Sky Take Out 完整启动与联调流程（Windows）

本文档对应项目目录 `D:\software\sky-take-out`，推荐优先使用 Docker Compose。Docker 方式会同时启动 MySQL、Redis、Spring Boot 后端、商家 React 前端和用户 React 前端，避免本机版本与端口配置不一致。

## 一、当前安装位置与访问地址

- Docker Desktop：`D:\docker\desktop`
- Docker 的 WSL 数据：`D:\docker\wsl-data`
- 项目：`D:\software\sky-take-out`
- 商家端：http://localhost:8081
- 用户端：http://localhost:3000
- MySQL（需要本机工具连接时）：`127.0.0.1:3307`
- Redis（需要本机工具连接时）：`127.0.0.1:6380`
- 后端 8080 只在 Docker 内部使用，不直接暴露到宿主机

## 二、首次安装后的必要重启

WSL、Virtual Machine Platform 或 Docker Desktop 首次安装后，必须重启 Windows。重启后：

1. 从开始菜单打开 Docker Desktop。
2. 等待右下角状态显示 Docker Engine 正在运行。
3. 打开 PowerShell，验证：

```powershell
& 'D:\docker\desktop\resources\bin\docker.exe' version
& 'D:\docker\desktop\resources\bin\docker.exe' compose version
```

若 `docker` 尚未加入 PATH，可在当前 PowerShell 临时设置：

```powershell
$env:Path = 'D:\docker\desktop\resources\bin;' + $env:Path
```

## 三、首次启动前准备（已经完成时不要重复覆盖）

进入项目：

```powershell
Set-Location 'D:\software\sky-take-out'
```

### 1. 环境变量

根目录必须有 `.env`。若没有，先执行：

```powershell
Copy-Item .env.docker.example .env
notepad .env
```

必须把所有 `replace-with-...` 替换为强密码。保留端口：商家端 8081、用户端 3000、MySQL 3307、Redis 6380。`.env` 已被 Git 忽略，不能提交到 GitHub。

### 2. 演示数据库初始化文件

仓库已包含 `docker\mysql\init\001-demo-seed.sql` 和 `002-demo-admin.sql`。它们只包含表结构、英文菜单、美元价格和通用演示管理员，不包含真实用户、地址或订单。文件只会在 Docker 的 `mysql-data` 卷第一次创建时导入。

商家端演示账号：`admin`，密码：`123456`。

若以后需要另外备份当前本机数据库，先确认本机 MySQL 正常，再执行：

```powershell
$env:MYSQL_PWD = '本机MySQL的root密码'
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe' `
  --host=127.0.0.1 --port=3306 --user=root `
  --single-transaction --routines --triggers --events `
  --set-gtid-purged=OFF --default-character-set=utf8mb4 `
  --result-file='D:\docker\backups\sky-take-out-private.sql' `
  sky_take_out
Remove-Item Env:MYSQL_PWD
```

私人 SQL 备份可能包含业务数据，必须保存在仓库外，不能上传公开仓库。

## 四、Docker 一键启动（推荐）

确保 Docker Desktop 已运行，然后在项目根目录执行：

```powershell
Set-Location 'D:\software\sky-take-out'
$env:Path = 'D:\docker\desktop\resources\bin;' + $env:Path
docker compose up -d --build
docker compose ps
```

首次启动需要下载基础镜像并编译，耗时较长。`docker compose ps` 中五个服务最终都应为 `Up`，带健康检查的服务应为 `healthy`。

查看启动日志：

```powershell
docker compose logs -f mysql
docker compose logs -f redis
docker compose logs -f backend
docker compose logs -f admin-web
docker compose logs -f customer-web
```

按 `Ctrl+C` 只会退出日志查看，不会停止服务。

## 五、完整联调检查顺序

1. 打开用户端 http://localhost:3000，注册或登录。
2. 浏览分类和菜品，加入购物车。
3. 进入结算页，新增或选择收货地址；确认不会再进入 404 页面。
4. 提交订单。当前项目不接第三方支付，点击支付会调用已有后端支付模拟接口并完成订单流程。
5. 打开商家端 http://localhost:8081，用原商家账号登录。
6. 在订单页面确认新订单出现；按原流程接单、处理、派送和完成。
7. 新订单通知继续使用项目原有 WebSocket 路径，Nginx 已保留 Upgrade/Connection 头。
8. 若页面没有即时刷新，检查：

```powershell
docker compose logs --tail 200 backend
docker compose logs --tail 100 admin-web
```

## 六、日常操作

停止并保留数据库：

```powershell
docker compose down
```

再次启动：

```powershell
docker compose up -d
```

代码修改后重新构建：

```powershell
docker compose up -d --build
```

查看状态与资源：

```powershell
docker compose ps
docker compose images
docker compose logs --tail 200 backend
```

重要：不要执行 `docker compose down -v`，它会删除 Docker 内的 MySQL 和 Redis 数据。只有明确要清空容器数据库并重新导入 SQL 时才能使用。

## 七、不使用 Docker 的本地开发启动方式

不要同时运行 Docker 版和本地版同一前端，否则 3000/8081 端口会冲突。

### 1. MySQL

启动本机 MySQL 8，确认 `127.0.0.1:3306` 可连接，并存在 `sky_take_out` 数据库。后端本地配置位于 `sky-server\src\main\resources\application-dev.yml`。

### 2. Redis

在一个 PowerShell 窗口执行：

```powershell
Set-Location 'D:\redis'
.\redis-server.exe .\redis.windows.conf
```

再开一个窗口验证：

```powershell
Set-Location 'D:\redis'
.\redis-cli.exe -a 123456 ping
```

应返回 `PONG`。如果提示 6379 拒绝连接，说明 Redis 服务端没有启动，单独运行 `redis-cli.exe` 不能启动 Redis。

### 3. Spring Boot 后端

在 IDEA 中打开 `D:\software\sky-take-out`，等待 Maven 完成，然后运行：

`sky-server\src\main\java\com\sky\SkyApplication.java`

默认端口为 8080。若提示端口被占用：

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select-Object OwningProcess
Get-Process -Id 上一步的进程号
Stop-Process -Id 上一步的进程号
```

只停止确认属于旧后端的 Java 进程。

### 4. 商家 React 前端

```powershell
Set-Location 'D:\software\sky-take-out\sky-frontend-admin'
npm install
npm run dev
```

按 Vite 终端显示的地址访问。该前端继续调用原 `/admin` API 和原 WebSocket，不修改后端协议。

### 5. 用户 React 前端

```powershell
Set-Location 'D:\software\sky-take-out\sky-frontend-user'
npm install
npm run dev
```

按 Vite 终端显示的地址访问。用户端继续调用原 `/user` 和 `/notify` 接口。

## 八、CI/CD

GitHub 仓库：`https://github.com/JacksonXue2004/sky-take-out`

- `.github\workflows\ci.yml`：提交和 Pull Request 时构建 Java 后端、两个 React 前端及三个 Docker 镜像。
- `.github\workflows\publish-images.yml`：合并到 `main`、推送 `v*` 标签或手动运行时，将镜像发布到 GitHub Container Registry。
- 发布镜像：`sky-backend`、`sky-admin-web`、`sky-customer-web`。
- 回滚时在生产环境 `.env` 中把 `IMAGE_TAG` 改为先前的 `sha-提交号`，再执行 pull 与 up；这不会修改数据库卷。

生产服务器命令：

```bash
docker compose -f compose.production.yml pull
docker compose -f compose.production.yml up -d
docker compose -f compose.production.yml ps
```

## 九、常见问题

### Docker 提示无法连接引擎

先打开 Docker Desktop 并等待 Engine running。若刚启用 WSL/Virtual Machine Platform，重启 Windows。再执行 `wsl --version` 和 `docker version`。

若日志提示 `HCS_E_HYPERV_NOT_INSTALLED`，但任务管理器显示 CPU 虚拟化已启用，以管理员身份打开 PowerShell，执行：

```powershell
bcdedit /set hypervisorlaunchtype auto
```

然后重启 Windows。可用下面命令确认系统已加载虚拟机监控程序：

```powershell
Get-CimInstance Win32_ComputerSystem | Select-Object HypervisorPresent
```

结果应为 `True`。

### 端口被占用

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 3000,8080,8081,3307,6380 | Format-Table LocalAddress,LocalPort,OwningProcess
```

确认进程身份后再停止，不要盲目结束系统进程。

### 修改 `.env` 后没有生效

```powershell
docker compose down
docker compose up -d --build
```

### 修改 SQL 后数据库没有重新导入

初始化 SQL 只对空卷执行。保留数据时不要重建卷；如果确实需要完全重置，应先另行备份数据库，再明确执行 `docker compose down -v`，之后重新 `up`。

### Redis 修改营业状态仍报连接失败

Docker 模式检查 `docker compose ps redis` 与 `docker compose logs redis`；本地模式检查服务端是否启动、密码是否为后端配置中的值、端口是否为 6379。Docker 内部后端连接服务名 `redis:6379`，不是宿主机的 6380。
